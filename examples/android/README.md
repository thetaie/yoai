# The Android lane

Two activities against one `yoai_core`, and they are different things:

| | Activity | What |
| --- | --- | --- |
| **The app** | `HomeActivity` | The home screen — current state, the nine-cell grid, the last 24 hours |
| **The bench** | `MainActivity` | One screen of measurements, from before there was an app |

Both are launchable, under different labels, and the bench's `<activity>` block
is what a release manifest drops. The rest of this file is about the bench; the
app's half is [the design](../../design/README.md) and the store rules in
[src/store/timeline.hpp](../../src/store/timeline.hpp).

## The app

Home is a **state switcher**, not a log. Tapping a cell does not record an
event — it makes that state the current one, which closes the previous entry at
the same instant and writes its duration. That is the whole reason a day comes
out continuous with nobody back-filling it, and it is why there is no "add an
entry" control anywhere on the screen. Ending is the separate gesture and leaves
a gap on purpose; nothing fills one in later.

None of those rules is implemented here. They are in the core, behind the
`yoai_timeline_*` half of [src/yoai.h](../../src/yoai.h), and
`day/Timeline.kt` is a JSON reader over it with no opinions of its own. The list
on the home screen is a **rolling 24-hour window**, deliberately not "today" —
see design/README.md for why the two are not interchangeable.

Colors come from `ui/Palettes.kt`, generated by
`design/make-compose-palettes.py` from `design/palettes.json`. Do not hand-edit
it, and do not reach for `dynamicColorScheme`: Material You reads the wallpaper,
which is a seventh palette the design does not have. The bench's own
`ui/Theme.kt` still follows the device, and stays that way — it is a set of
readings rather than a designed surface.

Strings are Chinese in `values/` and English in `values-en/`, matching
harmony's `base`. The other nine of the eleven interface languages have
directories on the HarmonyOS side and not here yet; see
[design/i18n-status.md](../../design/i18n-status.md).

## The bench

One screen of measurements against the same `yoai_core` the HarmonyOS lane
runs, so a figure taken here and a figure in
[design/voice.md](../../design/voice.md) are comparable.

The reason it exists is that every number in that file was taken on one chip, a
Kirin 9020, and several of its conclusions are about the chip rather than about
the engines — the codec decode that five attempts could not move, the throttle
step at thirty seconds, the bandwidth ceiling that bounds decode, and the GPU
that HarmonyOS killed by policy before it could be timed. None of those is
settled until a second device disagrees or agrees.

## What it measures

| panel | needs | reads |
| --- | --- | --- |
| Device | nothing | SoC, cluster shape, and the arm64 feature words — see **-march** below |
| Memory bandwidth | nothing | GB/s swept one thread at a time |
| Speech out | two GGUFs | per-stage timings and RTF, from the engine's own object |
| Recognition | a GGUF and a WAV | transcript, prosody, and RTF timed here |
| On-device LLM | a GGUF | prefill and decode split at the first `reply` event |

Everything prints the engine's own JSON under the one derived figure worth
reading at a glance. That is deliberate: design/voice.md is largely a record of
conclusions drawn from numbers that turned out to be something else, and the
cheapest defence is never hiding the object a figure came from.

## Building

```
cd android
python build.py          # deps, the LLM engine, the APK -- the first run
python build.py apk      # every run after that
python build.py qtts     # add speech out
python build.py vulkan   # add speech out with ggml's Vulkan backend, for Adreno
```

The same script on every platform (`python3` on macOS/Linux).

**A lane is on when its SDK exists.** `prebuilt/llama-sdk/<abi>/` turns on the
on-device LLM and recognition together; `prebuilt/qtts-sdk/<abi>/` turns on
speech out. Nothing in a tracked build file names a machine-local path, and the
Device panel prints which lanes came out on.

Android Studio is for editing and debugging, not a build dependency. Open
`examples/android/` in it when you want it.

## -march is asserted, not detected

A cross build with no `-march` lands on baseline `armv8-a`, because CMake's
feature probes compile **and run** a test binary and cannot run one for the
phone. design/voice.md measures that costing 2.9x prefill and 2.2x decode.

So `build.py` asserts a feature set, and its default is the Kirin's:
`armv8.6-a+i8mm+bf16+dotprod+fp16`. A current Qualcomm core is armv9.2-a and has
more. **The Device panel is how the assertion gets checked** — it prints what
the chip reports, and `sve2` showing up there against a build that never asked
for it is a lever nobody has pulled yet.

```
python build.py llama arch=armv9.2-a+i8mm+bf16+dotprod+fp16+sve2
```

Keep the default when the point is comparing against the Kirin figures, and
change it when the point is finding this chip's ceiling. Those are different
questions and the same script answers both.

## Models

Pushed by hand, to a directory that needs no permission:

```
adb push <file> /sdcard/Android/data/com.yoai.bodyclock/files/
```

The Models panel lists what is actually there, and the app's own path is
printed above it in case the package name ever changes. Nothing here downloads
or manages a model — this is a bench, and which checkpoint is on the device is
part of what is being recorded.

## What is not here

- **No chat, settings or session storage.** The HarmonyOS lane has all of it and
  this one is not a port of that. What the app half does have is the day log,
  which the HarmonyOS lane does **not**: its `Index.ets` is still the chat
  screen, so the home screen designed in round 5 exists here first.
- **No screen behind the floating button.** Ask, Today and Settings are separate
  rounds of the design; the pills open nothing yet rather than navigating
  somewhere empty.
- **No recording.** Every clip in design/voice.md is a file, so the bench reads
  files and never asks for a microphone.
- **No playback.** `nativeTtsSay` takes an optional sink and the bench passes
  none: copying a megabyte of samples across the bridge to discard them would
  be part of what the stopwatch measured.
